# Faryo v1.11.11 Error Contract and Recovery Plan

状态：实施中

## 目标

把 Owner、Gateway 和浏览器目前以自由文本为主的失败路径收敛为一套版本化、隐私安全、
向后兼容的错误契约。用户应看到具体原因和下一步操作，而不是笼统的 `Action failed`、
`Codex thread lifecycle request failed`、HTML 解析异常或裸上游异常。

本计划及测试只记录匿名夹具、错误类别和状态码，不记录真实会话正文、thread id、本机路径、
域名、账号、Token、Cookie 或上游认证材料。

## 已确认的问题

1. Owner 的 `OwnerError` 只有自由文本和 HTTP 状态；ASGI 响应没有稳定错误码、重试语义或
   恢复建议。
2. Codex 生命周期 RPC 的原始错误会被完全压成通用文案。归档一个仍在 CLI 中打开的 thread
   虽然正确返回 `409`，主页无法告诉用户应先关闭另一个 Codex 客户端。
3. Gateway 的 New、Resume、Archive 和 Restore 路由重新构造错误 JSON 时会丢掉 Owner 的
   结构化字段。
4. 非 JSON、认证页、服务重启、超时和普通业务冲突最终都进入同一个 `Action failed` 弹窗。
5. Owner 对话页只显示 `HTTP N: text`，无法利用错误码或恢复建议；后台刷新错误仍应保持安静。

## 设计决定

### 版本化错误信封

失败响应继续保留现有 `ok: false` 和 `error`，并增加：

- `errorContractVersion`：错误契约版本；
- `errorCode`：稳定、可测试的机器码；
- `errorTitle`：短标题；
- `retryable`：相同请求是否适合稍后重试；
- `recovery`：不含私密数据的用户操作建议。

现有 `envelopeVersion` 保持不变，旧浏览器仍可只读取 `error`。新字段只能增加，不能让普通
reload 或旧部署发生协议冲突。

### 集中映射与隐私边界

1. `faryo_cli.error_contract` 是 Owner 和 Gateway 共用的唯一错误分类表。
2. 认证、CSRF、权限、找不到、参数、目录选择、会话占用、运行上限、App Server 重连、
   上游不可用、超时、响应损坏和内部错误使用稳定码。
3. 已知业务错误使用审核过的固定文案；未知 5xx 永远不向浏览器转发异常字符串。
4. 任何保留的参数错误都移除控制字符、绝对路径、UUID、Token/Secret/Password 样式值并
   施加长度上限。
5. Gateway 只转发允许的结构化错误字段；控制审计继续只记录动作、目标摘要、状态和耗时。

### 浏览器展示

1. Gateway 主页依据 `errorTitle`/`errorCode` 显示具体标题，并把 `recovery` 与原因分段展示。
2. Owner 对话页保留紧凑错误条，但显示恢复建议；不再默认给所有业务错误加无意义的
   `HTTP N` 前缀。
3. HTML 登录页、非 JSON、断网和 502/503/504 在浏览器本地也生成同一结构化 Error 对象。
4. 后台轮询、SSE 重连和取消仍不弹窗；可靠发送继续按 `retryable` 和幂等消息 id 处理。

## 实施阶段

- [x] Phase 1：新增共享错误契约、OwnerError 元数据和 Owner ASGI 规范化。
- [x] Phase 2：Gateway 自动规范化所有 `ok: false` 响应，并保留 Owner 错误字段。
- [x] Phase 3：Gateway/Owner 浏览器读取 `errorCode`、`errorTitle`、`retryable` 和 `recovery`。
- [x] Phase 4：覆盖归档占用、认证/CSRF、参数、目录、上限、重连、超时、非 JSON 和未知 5xx。
- [ ] Phase 5：完整 source/browser/部署验证，普通 reload，推送并发布 source-only v1.11.11。

## 验收条件

1. 打开中的 Codex thread 归档失败显示“Conversation still open”，并明确要求关闭另一个
   Codex 客户端后重试；原始 thread id 和路径不进入响应。
2. 401/403、409、404、413、502/503/504 和未知 500 具有稳定且正确的错误码、标题和
   `retryable`。
3. Gateway 的 New、Resume、Archive/Restore 不丢失 Owner 错误语义或 HTTP 状态。
4. HTML 登录页和非 JSON 上游不再产生 `Unexpected token '<'`。
5. 错误响应、控制审计、日志和公开测试中不出现正文、Token、Cookie、邮箱、域名或真实路径。
6. 可靠发送、App Server 流式、Markdown/TeX、历史、目录选择、认证、tmux 几何和普通 reload
   不回归。
