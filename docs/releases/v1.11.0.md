# Faryo 1.11.0

Faryo 1.11.0 makes Codex session commands and tool activity visible without
turning either into noisy transcript text.

## Changes

- Browser-issued mutating slash commands use a private, bounded lifecycle with
  stable identity and `running`, `waiting`, `completed`, or `failed` states.
  `/rename`, model selection, Fast mode and permissions remain outside model
  context and survive an ordinary browser or Owner reload.
- Tool items retain their official command, file-change, search, MCP or generic
  type instead of relying on English text prefixes in the browser.
- Completed activity stays collapsed; running, waiting and failed groups expose
  their state immediately. Unknown future Codex items fall back to a safe
  generic card rather than disappearing.
- Command output, tool results and file diffs are fetched only after explicit
  expansion through an authenticated, no-store endpoint. Per-field and total
  limits keep large histories responsive.
- Durable rollout call/result pairing restores bounded details after an Owner
  reconnect when `thread/read` no longer includes the completed tool item.
- Answer copy continues to use original Markdown/TeX and excludes command rows
  and activity cards.

## Privacy and compatibility

- Faryo still does not create a second prompt/answer database.
- The command timeline excludes Goal objectives, read-only panels, unknown
  free-form arguments, credentials and message bodies; it uses private atomic
  storage with `0700`/`0600` permissions.
- SSE replay and diagnostics remain body-free. Hidden reasoning is never
  returned as tool detail.
- Codex App Server remains the default backend; existing Codex TUI (tmux)
  sessions use the same command display model without changing tmux geometry.

Faryo remains source-only. Release assets contain the reviewed installer,
source archive and SHA-256 manifests when this version is tagged.
