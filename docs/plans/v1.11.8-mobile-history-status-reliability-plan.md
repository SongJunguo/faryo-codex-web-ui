# Faryo v1.11.8 Mobile History and Status Reliability Plan

状态：实施中

## 目标

修复 Codex TUI 历史在 Chat 视图中的消息边界丢失、移动端末条消息被底部状态覆盖、窄屏顶部状态信息不可查看，以及多行输入时附件/发送按钮横向挤占正文的问题。修复必须保留 Faryo 的可靠发送、完整历史分页、问题导航、Markdown/TeX、复制、移动键盘布局、App Server 流式路径和 tmux 几何边界。

本计划及其证据只记录匿名统计、通用路径和测试夹具，不记录真实对话正文、Token、Cookie、邮箱、域名、会话名称或本机私人目录。

## 已确认的问题

### 1. TUI JSONL 消息边界在浏览器前丢失

Codex rollout JSONL 已经提供每条记录的 `role`，但 TUI 历史分页接口目前把一个 turn 重新拼成带 `›`/`•` 前缀的单段文本。浏览器随后又用终端启发式规则切分这段文本。

当用户消息本身包含 Codex 启动画面、目录信任提示或以 `›` 开头的引用时，一条真实消息会被拆成多个假用户气泡或 process 行。匿名实测中，最近 12 个权威 turn 被渲染为 16 个用户气泡，其中 4 个没有问题 key，至少 1 个已加载问题的 key 与预览错配。

连带风险：

- 问题导航可能跳到错误气泡；
- 单消息复制和 Markdown/TeX 渲染可能使用错误边界；
- 引用的终端文本可能被误判为活动状态；
- 长历史每次刷新都重复解析大段拼接文本，增加 DOM 变动。

### 2. 折叠底部状态不属于布局测量范围

折叠状态行使用绝对定位并向 footer 顶部外延伸。composer reserve 只测量 footer 自身高度，因此版本按钮可能覆盖最后一条消息。固定增加像素不能覆盖字体、视口、键盘和状态行高度变化。

### 3. 窄屏顶部状态被截断

顶部 Context、Week、model、speed、Goal 和 Git 状态被放进一个 `overflow: hidden` 的单行 flex 容器。小屏只能看到前后片段，无法通过触摸查看中间内容。

### 4. 多行输入的操作按钮挤占正文宽度

手机 composer 把松鼠、textarea、附件按钮和发送按钮全部横向排列。输入变成多行后，附件与发送两个按钮仍各占一列，正文区域明显变窄，换行和纵向增长进一步加剧。

### 5. TUI 与 App Server 短名不在一个权威命名域

两个 backend 都使用 `faryoN` 作为浏览器短名，但分别由 tmux 和 App Server 私有注册表持有。当前实现依赖每个调用者手工把另一 backend 的名字作为 `reserved_names` 传入；新建 TUI 已传递，而恢复 TUI 的路径遗漏了这个参数。

如果 App Server 已经占用一个短名，后恢复的 TUI 就可能创建同名 tmux。Owner 随后只看裸 `session=faryoN`，并优先检查 App Server，于是一个有效 TUI 链接会静默打开另一条 thread。启动时迁移只能修复启动前已有冲突，不能防止运行期间遗漏的新入口。

### 6. Codex 补丁版本升级造成已验证本地命令误阻塞

本机 Codex 已升级到 0.149.1，而 Faryo 的 `availableDuringTask` 能力快照仍停留在 0.149.0。运行时命令名称虽然没有漂移，安全策略仍会在版本不一致时撤销忙碌期能力，导致 `/goal clear` 被错误返回 409。

[Codex 0.149.1 的官方 TUI 源码](https://github.com/openai/codex/blob/rust-v0.149.1/codex-rs/tui/src/slash_command.rs)明确把 `Goal` 列入 `available_during_task`，并有对应源码测试。本轮把测试版本更新为 0.149.1；未知未来版本仍不得从旧快照继承忙碌期能力。

## 同类开源项目证据

### DeepSeek Harness

[DeepSeek Harness Session 类型](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/session/src/types.ts)把 `SessionId` 定义为 branded id；[Workspace 设计](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/workspace.md)同样使用生成的稳定 `WorkspaceId`，明确不使用可变化或可重复的路径/标题作为身份。Registry 是唯一解析入口，未知 id 或归属不一致会失败，而不是按近似属性猜测。

可借鉴：稳定 id 与显示标题分离；跨层只传类型化 id；registry 单点解析。

### YepAnywhere

[YepAnywhere Provider Session Identity](https://github.com/kzahel/yepanywhere/blob/main/AGENTS.md#provider-session-identity)要求 YA URL session id 始终是规范的用户侧身份，Codex thread id 等 provider-native id 只能作为显式映射，不能悄悄替换 URL、持久元数据或 UI 中的身份。

可借鉴：公开 session id、backend/provider 和 native thread id 是三个不同字段；映射必须显式，不能依赖字符串形状或路由优先级。

### HAPI

HAPI 曾出现与本问题高度相似的[错误 thread 路由问题](https://github.com/tiann/hapi/issues/446)。其[修复 PR](https://github.com/tiann/hapi/pull/448)最终采用 Hub 按 agent session id 去重、Web 再做显示安全网，并补充同 namespace、跨 namespace、active/inactive 和恢复竞态测试。PR 的多轮 review 也证明“发现后再 merge”容易丢 active state 或与恢复流程竞态。

可借鉴：数据层必须有 canonical native identity 和唯一性规则，UI 去重只能是安全网；Faryo 应优先在分配时阻止冲突并在解析时失败关闭，而不是运行中合并两个仍活跃的 backend wrapper。

## 设计决定

### 项目规则与实施边界

1. 所有 Python 验证先读取 `conda env list`，自动选择满足项目依赖的现有隔离环境；不得把依赖写入 Conda base。
2. “保持轻量”不等于拒绝依赖。只有在成熟、许可证兼容、可固定版本且能明显降低复杂交互维护成本时才引入库；生产资源必须本地打包，并进入常规测试。
3. 本轮优先渐进收敛现有 Preact/Owner 边界，不为单个问题重写框架；小型本地实现必须职责单一、可独立测试且维护成本更低。
4. 所有可变浏览器资产继续自动版本化；缺失或被拒绝的资产响应使用 `no-store`。部署验收以普通 reload 和新标签页为准，不得要求用户发现或执行 hard refresh。
5. 公开计划、测试和发布证据只使用匿名夹具与统计，不写入真实对话、主机目录、域名或认证信息。

### 权威结构化历史

1. TUI JSONL 分页接口在读取每条原始消息记录时直接生成稳定的 `messageBlocks`：保留 role、turn key、question key、稳定 record id 和原始正文。
2. `text` 字段继续保留，供 Raw、旧客户端和安全 fallback 使用；Chat 不再从该文本猜测消息边界。
3. History Controller 对 `codex-jsonl` 和 `codex-app-server` 都优先使用分页接口给出的 blocks。只有旧接口或真正的 terminal fallback 才使用文本启发式。
4. 问题导航只使用服务端 question key；嵌入正文的 `›`、工具样式文本和终端提示不得生成额外问题。

### 动态 footer footprint

composer layout 计算 footer 自身矩形与明确标记的外溢状态元素的联合高度。状态行折叠、展开、附件变化、字体变化和视口变化都通过现有 Resize/Mutation 观察链重新测量，不引入固定设备像素表。

### 可横向浏览的信息轨道

1. 窄屏 expanded header 的状态行改为单一横向信息轨道：内容不缩没，支持触摸/触控板横向滚动、隐藏滚动条、阻止滚动传播到页面横向溢出。
2. 保持标题行和主要操作按钮固定；不把正文、普通按钮网格或可自然换行内容改成横滑。
3. 已经采用相同语义的附件缩略图、Markdown 表格和代码块继续保留各自的局部横向滚动，不建立嵌套页面级横滚。
4. 信息轨道保留键盘可达性和清晰的可滚动语义。

### 自适应 composer 操作组

1. 附件和发送按钮使用一个语义明确的操作组；短输入保持现有横排，达到多行阈值后在手机上切换为右侧纵排。
2. 多行判定使用 textarea 的实际行高和内容高度，不使用设备型号或固定键盘像素表。
3. 使用进入/退出迟滞避免按钮纵横切换改变 textarea 宽度后反复抖动。
4. 纵排时附件在上、发送在下；按钮仍满足触摸目标尺寸，松鼠的中断语义不变。

### 单一会话命名域与失败关闭

1. 新增 Owner 级 `SessionNamespace` 作为 `faryoN` 的唯一生成与解析规则；tmux 和 App Server registry 不再各自复制编号算法。
2. TUI 新建/恢复和 App Server 新建/恢复都在同一 namespace lock 中从两个 backend 的实时联合集合分配名字。
3. read、write、SSE 和主页投影全部调用同一个 backend resolver。一个名字若同时被两个 backend 持有，立即返回 `409`，不得再按 App Server/TUI 优先级静默选择。
4. Owner 启动时原子迁移已有 App Server 冲突名，不终止 Codex thread 或 tmux；迁移后重新建立 actor 映射。
5. `faryoN` 继续作为兼容短名；backend 与 native thread id 保持独立字段。若未来引入不随运行 wrapper 变化的公开 opaque id，将作为单独协议迁移，不在本修复中用第二套临时映射叠加复杂度。

## 实施阶段

### Phase A：历史协议与浏览器消费

- [ ] 为 Codex JSONL turn 输出结构化 blocks，并保持现有分页字符预算与隐私边界。
- [ ] 让 History Controller 在 TUI Chat 路径使用 blocks。
- [ ] 增加包含嵌入 `›`、Codex banner、trust prompt、process-like 文本和 TeX 的匿名回归夹具。
- [ ] 验证问题 marker 数、用户 block 数、question key、复制源和公式渲染一致。

### Phase B：移动布局

- [ ] 动态测量 footer 外溢状态的真实 footprint，消除版本/状态与末条消息重叠。
- [ ] 为顶部状态信息实现窄屏横滑，并隐藏滚动条。
- [ ] 审查同类信息轨道；只在内容本质为单行连续元数据且自然换行会损害可读性时复用。
- [ ] 为附件/发送按钮建立多行输入时的手机纵向操作组，并验证切换无抖动。
- [ ] 验证 320、390、432 CSS px，large text、键盘开关、全屏和普通浏览器窗口。

### Phase C：回归、部署与发布

- [ ] 引入单一 SessionNamespace，修复 TUI resume 漏传保留名。
- [ ] 对 GET、POST 和 SSE 的双 backend 同名 fail closed；验证启动迁移保留两个后台 thread。
- [ ] 增加跨 backend 分配、恢复、重复请求、冲突解析和重启迁移测试。
- [ ] 对齐已核验的 Codex 0.149.1 命令能力，并保持未知版本 fail closed。
- [ ] 运行 Python 3.10/当前项目环境的 Owner/Gateway/CLI 单元测试。
- [ ] 记录 `conda env list` 的自动环境选择结果，并确认未修改 Conda base。
- [ ] 运行 Node lint、format、typecheck、bundle check 和浏览器回归。
- [ ] 运行 source-only canonical gate。
- [ ] 部署到本机现有服务，不重启或改写正在工作的 Codex/TUI 会话几何。
- [ ] 用真实长 TUI 会话验证普通 reload、历史边界、问题导航、末条消息和横滑状态栏。
- [ ] 检查 Owner、Gateway、App Server 和 Tunnel 日志无新增异常。
- [ ] 更新版本与公开发布说明，提交并推送 `main`。

## 验收标准

1. 一个包含 5 个字面 `›` 提示符的真实用户消息仍只渲染为一个用户 block，并只占用一个 question key。
2. TUI 最近 N 个 turn 的用户 block 数等于服务端权威用户消息数；不存在因嵌入终端文本产生的无 key 用户 block。
3. 复制该消息得到完整原文；Markdown、TeX 和代码围栏不跨消息串联。
4. 底部状态/版本与末条消息的相交面积在所有验收视口和字体大小下为 0。
5. 顶部状态轨道 `scrollWidth > clientWidth` 时可以触摸横滑到首尾；页面本身无水平溢出，标题操作仍可点击。
6. 手机短输入保持紧凑横排；三行及以上输入把附件/发送按钮纵排，textarea 获得更宽空间；删除到一行后恢复横排且不抖动。
7. App Server streaming、TUI Live、发送幂等、Esc send-now、问题导航懒加载和 Raw/Chat 切换无回归。
8. TUI/App Server 不会分配相同 `faryoN`；人工构造双重所有权时 API/SSE 返回 409 而不是打开错误 thread；重启迁移后两个后台仍存在且短名唯一。
9. 新静态资源可通过普通 reload 或新标签页获取，不要求 hard refresh。
10. 新增依赖为 0，或每项新增依赖均有许可证、版本固定、本地生产资产和测试证据；本轮不得用框架重写替代局部可靠性修复。
11. Codex 0.149.1 忙碌时 `/goal clear` 通过本地 TUI 命令路径执行；伪造未知版本时同一能力仍被撤销。

## 非目标

- 不修改 Codex TUI/tmux 宽高。
- 不把 TUI backend 改成 App Server backend。
- 不在这次修复中重写整个 transcript 或 header 框架。
- 不把所有被截断的标签无条件改成横向页面滚动；文件名、标题等仍可使用省略号和详情提示。

## 验证证据

实施完成后填写具体测试命令、匿名浏览器几何、部署版本、服务健康和普通 reload 结果。
